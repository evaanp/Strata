Branch `pla-0139` (worktree `~/strata-0139`), based on `v0.1.39` (6f32ec0, 2026-10-04).
Source: the 53 commits of `v0.1.38..prefix-park-analysis` (HEAD a5309b0, image `strata:0.1.38-pla1-prefix`).

Verdicts were decided by reading upstream v0.1.39's own code (not the release notes alone); every **drop**
names the upstream commit or released construct that covers it. Upstream's big parking change is PR #559
(merge e3978eb): batch slots, pipelined layer split, and parking that stores a split conversation as one
`SavedConversation` with per-stage `stage_images`, validated and restored stage by stage. PR #639 added the
per-card dense-weight trim (`--trim-stage-weights`, `STRATA_STAGE_TRIM`; on by default in HIP builds, opt-in
on CUDA). PR #578 added remote helper tiers (`RemoteExperts`, `--expert-cache-remoteN`). PR #583 batched the
PLE and embedding gathers of the prefill. PR #465 gave every batch slot its own session (parallel decode).

## The `parallel` question (upstream #465)

**Verdict: keep `"parallel"` out of the prod config for now; measure on the box before enabling.**
Everything below is read from this tree (the released 0.1.39 plus our port), so the pre-release caveats in
`~/strata-batch/ANALYSIS-batch-559.md` are re-checked against shipped code, not the fetched `bd400f7`.

**How it is switched on.** `"parallel": N` in the arena config maps to `--batch N`
(`serve/server.py:1495-1513`); `PARALLEL_MAX = 8` (`serve/server.py:1492`) is the engine's window cap
`kVerifyMaxT = 8` (`include/strata/kernels/verify_kernels.hpp:21`). The server reads the engine's real slot
count back and says when it is lower than asked (`serve/server.py:488-493`); the web monitor gets
`parallel`/`slots`/`outside_slots` (`serve/server.py:2139`). Nothing changes without the key.

**What it costs on our cards.** Each batch slot gets its own full `session_bytes(g, max_context, K, lo, hi)`
session **per stage card**, cudaMalloc'd at start (`src/program/generate.cpp:3288-3316`); if two do not fit,
`--batch` turns itself off with a warning (`:3319-3324`), and the engine prints that the slot sessions take
VRAM the expert cache would otherwise hold (`:3328-3330`). `session_bytes` scales with `max_cells`
(`src/core/session.cpp:54-73`), so at our `--max-context 153600` the per-slot price is the same structure as
the ANALYSIS §5 table (≈0.5 GiB CUDA0 + ≈0.37 GiB CUDA1 VRAM, ≈1.5 GiB pinned RAM per slot - those figures
are from the pre-release analysis and must be re-measured). Our per-stage dense trim already runs in prod
(#639's `--trim-stage-weights` is a no-op for us), so there is no trim headroom to bank: the slots come
straight out of expert-cache residency, which ANALYSIS measured as the dominant batch throughput risk
(205 -> 105 tok/s at 4 slots on their control run).

**What the release fixed since that analysis.**
- *Slot output is now parked.* `copy_from_slot` (`generate.cpp:6541-6560`) copies a finished slot's sessions
  back stage by stage, and the handler parks the outgoing conversation before any handover
  (`park_current`, `:7114`); an idle slot marks its state cached at BDONE (`:6626-6628`), and the RAM
  conversation cache wins over a slot-held copy when both match (`:7087`). The per-turn re-prefill gap is gone.
- *Our disk key rides the batch protocol.* `sampling_keys()` appends `conv=ID` on **both** GEN and BGEN heads
  (`serve/server.py:699`, used at `:884` and `:974`); the engine parses it in the shared read path
  (`generate.cpp:6850`).
- *Pipelining is legal on our two-card split*: `--batch-groups G` needs a layer split and G dividing N
  (`generate.cpp:3283-3286`; re-checked after any auto-shrink at `:3326`); piped windows run
  `GS = batch / groups` rows per stage (`:6658-6659`).

**What the release did NOT fix.**
- *Penalties are still hard-zeroed in batch windows*: `Verifier::sample_rows` copies each slot's
  `SamplerParams`, then `sp.penalty_last_n = 0;` and passes `nullptr` history (`src/core/verify.cpp:2050-2063`).
  Prod runs `presence_penalty 1.0` (thinking loops without it, measured on the box) - every batched turn would
  lose it. The ANALYSIS §4 patch (~100-150 lines: per-slot history ring -> existing `penalty_rows` ->
  existing `d_hist`) is still required before PLA uses batch.
- *No MTP drafts in slots*: `--batch-spec` does not exist anywhere in 0.1.39 (`grep -rn 'batch-spec' src serve
  tools` empty). The server's policy stands: a solo request keeps drafts; when a second arrives it is STOPped
  and re-admitted via `BGEN` with prompt + generated so far, prefix-exact through the prompt cache
  (`serve/server.py:874-1034`). Two concurrent PLA streams therefore decode at draftless window rate.

**Decision.** On two 16 GB cards with the split, `--batch 2` buys wall-clock concurrency (both conversations
advance between tool calls) at roughly today's aggregate rate, and risks expert-cache hit rate (+~1 GiB
VRAM/card) plus the penalty gap. Not worth shipping unmeasured: keep `"parallel"` absent, run the measurements
below on the box, and gate enabling on them. If penalties prove to matter (they will for PLA), land the ring
patch first; upstream is the right home for it - note it when #465 discussion continues.

## What to measure on the GPU box

All on 172.16.98.21 with the prod config as baseline; never enable `parallel` in the prod file until a row below passes its gate.

1. **Slot cost, at start**: engine lines `--batch: N slot sessions on CUDAx (X GiB each)` and `the slot
   sessions take X GiB of VRAM on CUDA0` (`generate.cpp:3316, 3328-3330`) with `--batch 2`; record free VRAM
   per card before/after. Gate: >= 1.4 GiB free stays on CUDA0 (vision's footprint).
2. **Expert-cache residency**: `decode expert cache hit rate` during a PLA-shaped run, solo vs `--batch 2`.
   A/B the `STRATA_STAGE_CACHE_SLOTS` pin (our `0ecfb32` port) if the rate drops >5 points.
3. **Rate**: two conversations alternating tool calls with `presence_penalty 1.0`; per-stream and aggregate
   tok/s for solo, `--batch 2`, `--batch 2 --batch-groups 2`. Confirm no `--batch-groups ... one group`
   warning (`generate.cpp:3283`). Gate: >= ~20 tok/s per stream (ANALYSIS §6).
4. **Follow-up TTFT after a slot finishes**: park-from-slot working = sub-second restore (#718 measured
   0.2-0.4 s for 254 MiB), not a re-prefill of the answer length.
5. **Penalty gap**: thinking-loop rate in batched turns vs solo (the `verify.cpp:2056` zeroing). Any rise ->
   the penalty-ring patch is mandatory before enabling; do not ship batch without it for PLA.
6. **Pinned RAM headroom**: process RSS with `--batch 2` while arena experts are pinned; hybrid keyless
   parking must keep honoring `--conversation-cache-min-free-mib 2048` - watch its refuse/skip log lines.
7. **Hybrid + disk parking under batch**: prefix hit then `BGEN` (`copy_to_slot` per stage) - extra copy
   cost; and a `conv=`-keyed conversation finishing in a slot must still reach disk (park-from-slot ->
   disk), restore in 0.2-0.4 s.
8. **Protocol edges**: `tools/batch_test.py` (greedy token-exact vs solo) with our `--layer-split 30`,
   `tools/early_close_test.py`, and a client disconnecting mid-slot (`BSTOP`, `serve/server.py:792-796`).
9. **Monitor**: web Monitor shows per-slot rate windows and `outside_slots` (server status line 2139) -
   cosmetic, but the PLA operators watch it.
