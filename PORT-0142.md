## Replay damage and how it was found (this is the expensive part)

Three classes, all silent until built or audited:

1. **Committed conflict markers.** The first rounds' resolutions committed `<<<<<<<`/`>>>>>>>`
   lines into 9 files (33 hunks). Repaired in `4347b42`; verification must be
   `git grep -n '^<<<<<<< \|^>>>>>>> ' HEAD` empty after every `--continue`, not at the end.
2. **Marker-surgery residue.** A stray column-0 `)` from a hand-cut hunk breaks the build
   far from its cause (`4347b42`, `15acd5a` after the first failed build). Sweep `grep -rn '^)$' src include` before each build. The `\r` inside committed
   marker lines makes python universal-newline line numbers disagree with grep - read
   `open(p,'rb').read().decode().replace('\r','')` when doing line surgery.
3. **Replayed commits that dropped or duplicated blocks.** `5f5681c` deleted the
   `live_conv` declaration and pasted the disk-parking block (and the `Options` fields) twice; in the
   old history that was hidden by a later squash-merge (`f504c2c`) which re-added the line -
   and flattening the history in a rebase drops squash-merges' fixes. `5df6dc7` pasted `post_multi`
   onto upstream's own copy (8bd6a26). `2c3983d`'s replay lost whole constructs that no compile error
   caught: the three keyless/hybrid parking tests in `conversation_cache_test.cpp`, the
   OnDevice drain counters and the `split_fixture(format)` call in
   `conversation_validation_test.cpp` main (defined, never run), both spill-tier test files (and
   CMake's `if(EXISTS ...)` turned each missing file into a silent skip), and the monitor's
   per-GPU cards' data path (`telemetry.py` `mem_free`/`names`/`gpus` payload, the
   `gpu-grid` container, its CSS - while `app.js` kept rendering into a missing
   element). Repaired in `b277286` and the two commits before it.

The catch-all that found class 3 in one pass: a **reverse-coverage audit** -
for every file where `pla-0140` and `pla-0142` differ, diff the two trees line-multiset-wise
and ask, for every line the OLD prod tip had and the new lacks, whether upstream's own
`1735d647..v0.1.40.2` diff explains it (line deleted or reworded upstream). What is
left unexplained is our lost content. It flagged exactly the five real losses; every
other hit was a refactor (the `drive.d.remote` fill now runs over `helper_tiers`, registering CLI
and spill tiers alike - wider than the old prod's CLI-only loop), an upstream superset
(`Vision.download` now carries the OSError-to-ValueError mapping we patched in 0.1.40), or a
reword with a longer tail.
