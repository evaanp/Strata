Nothing in the six picks **builds** on #848 - all six applied on `pla-0139` (which has no #848) and the
whole engine builds against CUDA 13 in the builder image.

111.2/111.4 tok/s; `--adapt-async 1` serial loop 117.3/109.6; both 121.7/126.3/120.9 - about +10%
over the pipeline alone.  **Arena numbers on our machine are unmeasured; the plan at the end produces

## Penalties inside the pipelined loop (e455258)

The task's hard part.  #859 refused `penalty_last_n > 0` and ran such requests serially; production
requests set `presence_penalty`/`frequency_penalty`, so pipelining would have died on real traffic.

The sampler takes its history as per-window rows: row t holds the `penalty_last_n` tokens preceding the
pick at window position t, computed by `penalty_rows` from a consumed tail plus the window.  The serial
loop computes them as it goes; the pipelined loop must have them **before** stage 0 launches window
K+1, i.e. before K's verdict exists.

The design, and why it is exact:

1. **A window's rows are built as the consumed tail then standing plus the chain's assumed tokens** -
   the MTP chain drafts window K+1 from the assumption that K is kept whole (its row-0 token is the
   guessed bonus).  So the row set for K+1 is computed against
   `consumed + window_K` before K commits anything.
2. **Stage the rows only on the on-path decision.**  A speculative window reaches the shared history
   buffer only when its launch actually happens, which is only when the assumption behind it is
   proven; a rejected speculative window never samples and never writes the buffer.
3. **The rebuild is the re-stage.**  When K is rejected, stage 0 restores its GDN state from the
   snapshot and rebuilds K+1 from the real tokens - and the rebuilt K+1's rows are simply computed
   again from the real consumed tail.  For the penalty history there is nothing else to unwind,
   because a rejected window's assumed rows never entered the buffer.
4. **Ordering on the stream.**  Staging is a `cudaMemcpyToSymbolAsync` on the stage's own stream,
   enqueued before the window's launches there; `pl_finish` samples and syncs on that stream before
   the picks are read, so no other window's upload can interleave ahead of a sampler read on the same
   stream.  One conversation per decode loop makes the per-stage buffer (a device symbol) safe.

Both loops now share the bookkeeping: `include/strata/core/penalty_hist.hpp`, `PipePenalty` -
`stage(window, T)` (compute rows into the staging buffer) and `commit(window, a)` (the consumed tail
gains `window[0..a]` after a verdict).  The serial loop pushes one window at a time; the pipelined
loop stages proven windows and commits real verdicts - **the same functions, so the pipelined loop
stages the serial loop's bytes by construction**.  The gate clause refusing penalties was removed.
With `STRATA_IQ_MT_MIN=1` the emitted tokens are then bit-identical to the serial loop's; sampled
requests agree given the same draws.

`penalty_hist_test` (`src/core/penalty_hist_test.cpp`, registered in CMake beside `coupled_draft_test`)
replays the pipelined loop's decision structure with production's own `penalty_rows` and the new
`PipePenalty`: chains are built **before** verdicts (the assumption `consumed + window`), windows are
proven (full accept, bonus guess right) or rejected, rejected ones never stage, and each on-path window
re-stages from the real tail.  It checks against an independently maintained serial ground truth:

1. the pipelined consumed tail equals the serial ledger at every stage point;
2. every staged row set equals the serial ground-truth rows byte-for-byte;
3. a proven speculative window's staged rows equal what was computed under the assumption when it was
   built - the re-stage after a rejection is asserted by construction and by 4;
4. no rejected window's token ever appears in a staged row (its guess token that *matched* the real
   bonus excepted - that token is legal and becomes the next window's `window[0]`).

`hist_n` in {0, 1, 7, 60, 512} (the 512/`hist_n=1` pair shows padding and truncation), windows to
`kVerifyMaxT`, 200 seeded scenarios x 60 rounds.  **Proven red**: making `PipePenalty::commit` a no-op
(the rebuild never happens) or one token short (replayed with `a` instead of `a + 1`) each fails
22,920 checks.  The `penalty_rows` kernel itself is unchanged and shared with the serial loop.

#904's own checks - `pdl_parity --replays N` and `verify_batch_parity` - need a CUDA card (they open a
device, no skip path); they compile here and run on the machine, below.

## The GPU machine: verification and measurements

Machine: RTX 4060 Ti (first stage, `gpu: [1,0]` says Ada first) + RTX 5060 Ti (last stage: layers
20-47 + head + MTP draft), `layer_split 20`, Ryzen 7 9700X, ~58 GiB RAM, arena mode.  Build the branch
with the machine's own CUDA (archs 89;120).

**1. #904 bit-identical proof (before any pipelining experiment):**

```
<build>/pdl_parity --replays 200      # PDL graph vs the plain graphs, per card: prints sm_ and
                                      # pdl_supported(); must report 0 differing replays
<build>/verify_batch_parity           # batched Q4_0 KV append + PLE post-ops vs the plain path
```

Note: the RTX 2000 Ada is sm_89 and the RTX 5060 Ti sm_120. `pdl_supported()` needs sm_90+, a CUDA
12.3+ build and code built for the card: our build (CUDA 13, `CMAKE_CUDA_ARCHITECTURES=89;120`) meets it on
the **5060 Ti**, so PDL runs on that stage and stays off on the Ada stage. Run `pdl_parity` on the 5060 Ti.
The mixer graph branches, batched KV append and PLE post-ops run on both.  Then replay the engine at greedy (`temperature 0`, `STRATA_IQ_MT_MIN=1`) with the production args
and compare token-for-token against the `pla-0139` binary: same tokens expected (#904 claims
bit-identical; upstream's own tests reported 0 of 200 replays differing on RTX 5090 + 4060 Ti).

**2. Serial vs pipelined, with penalties.**  Same server as production
(`PROD-strata-iq3_s.arena-0139-rev20.json`), env `STRATA_DECODE_TIMING=1` and
`STRATA_IQ_MT_MIN=1`; two runs over the same 22-request battery (five languages, thinking on/off,
code, temperature 0), requests carrying `presence_penalty: 0.6, frequency_penalty: 0.4` (the
penalty-branch path - the requests production actually sends, plus the repeat-penalty form):

- A: production args unchanged (pipelining off);
- B: args + `"--pipeline-windows", "2"`.

Compare A vs B **token-for-token per request**: must be identical - that is the penalty-through-the-
pipeline exactness check end-to-end.  Repeat B with `STRATA_PIPELINE_FORCE_MISS=2` (forces rejections
so the rebuild path runs constantly): still identical, no degenerate text - that is the penalty
rebuild under stress.  Record, from the engine's own lines:

```
strata pipeline: N windows ... X speculative, Y on the path, Z rolled back, W below the gate (theta)
strata pipeline classes: fresh ... | speculative ... | forced-chain disagreements, chain late
```

- decode tok/s serial (A's decode timing line) vs pipelined (B's);
- fraction of windows that ran pipelined = Y / (N - W) (W refused the gate);
- rollbacks = Z (and forced disagreements / late chains from the classes line);
- the Monitor's `pipelined loop:` watchdog line for state sanity.

`--adapt-async 1` stays off there (arena - the gate prints "it needs the resident RAM mode,
--resident-experts"); do not chase it until someone ports #848.

**3. Split sweep.**  Today `layer_split 20` balances the **sum** of the stages (measured +6% decode,
-4% prefill against the old order).  With pipelining the cost of a window approaches the **slower**
stage, so the balance point moves: matching per-stage time by bandwidth alone
(4060 Ti ~288 GB/s, 5060 Ti ~448 GB/s) wants ~0.64 x the layers on Ada, i.e. ~19 of 48; the head and
the MTP draft sit on the 5060 Ti, which pulls it back up 1-2 layers.  Sweep `layer_split` in
{16, 18, 20, 22, 24} x {pipeline off, `--pipeline-windows 2`} at two context lengths (8k and 32k),
greedy, and take the argmax decode tok/s for each mode - expect the pipelined optimum around 18-20
and serial's to stay 20.  Keep production at `layer_split 20`, `--pipeline-windows` off, until these
numbers exist; adopt pipelining only if the token-for-token checks in (2) pass and decode gains hold
across both context lengths.  Prefill must not regress: pipelined windows overlap decode windows only
(`--pipeline-windows 1` overlaps prompt short reads; measure it too, but keep it opt-in).
