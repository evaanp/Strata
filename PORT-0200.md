## Repairs the gates found

1. **`serve/test_server.py` (both lines):** 0.2.0 moved child containment into
   `serve/lifeline.py`, so `serve.server.contain` no longer exists. The tests
   now patch only `subprocess.Popen`.
2. **`serve/test_server.py` (prod line):** the merge took upstream's
   `MergingTokenizer`, which only overrides `encode()`. 0.2.0's
   `PromptEncoder` drives `encode_marked`, so `SampledIds` failed. The 0.1.45
   repair (`_merge` + `encode_marked`) is restored.
3. **`serve/test_kv_pool.py` (full line):** 0.2.0 defaults `fit_max_tokens=True`
   and clamps `max_tokens` instead of returning 400. The
   "400 before the engine" case now runs in strict mode
   (`fit_max_tokens=False`); the invariant it checks is unchanged.
4. **`cmake/strata_ggml_tq_overlay.cmake` (both lines):** upstream used
   `CMAKE_SOURCE_DIR`, which is the consumer's top-level directory when the
   fork is added as a subproject (sexec). The sexec configure failed looking
   for `<sexec>/third_party/ggml-tq/tq.cuh`. It now uses
   `CMAKE_CURRENT_SOURCE_DIR`; the fork's own build is unchanged.
5. **C# `tests/StrataSharp.Interop.Tests/fixtures/prepare_oracle.py`**
   (commit `6a619e7` in the C# repo): the oracle fake now matches 0.2.0's
   `prepare()` surface (`_note_unreadable_tool_images(messages, cancel)`) and
   provides `prompts`, `offline`, `last_image_at`, `_turn`, `_vision_up`.
   The Vision differential test passes against the rebased fork.
