## What 0.1.44/0.1.44.1 brings (box-relevant, 2-GPU split + RAM-resident experts)

- `mtp_first` (0.1.44, AMD-multi-GPU section): the drafter can sit on the FIRST
  stage's card when its draft head is the subset file (`draft_vocab.bin` beside
  `--mtp`, `spec >= 2`, `pipeline_windows >= 2`, `batch == 0`). Default ON only
  for HIP gfx1200/1201; on CUDA opt-in `STRATA_MTP_STAGE0=1`. Our disk parking
  is adapted (draft_dev); the pipeline-auto stage minimum drops to 2 with it.
- `--adapt-async 1` now works in arena mode (#1904): the adaptive tier's swaps
  run on a job thread. Off by default; answers with the tier on differ slightly
  from the blocking tier. Also fixes a real race: a K/V grow could lend a slot
  a swap was still writing - the class our split_ring sizing lives in.
- `STRATA_PIN_BY_NEED=1` (#1905, opt-in): pins the experts the GPU will not
  hold in expert-profile ORDER instead of an arena prefix, plus a second tier
  for the adaptive tier's swapped-out experts (`STRATA_ARENA_PIN_GIB` budget).
  Described as a Windows/WDDM feature (CUDA and HIP) - on our Linux box the
  prefix pin behaves as before; not enabled.
- `STRATA_PCIE_MIN1=1` (opt-in): one miss goes over PCIe as soon as a layer has
  two (the share otherwise rounds to 0); only flies if the blob is pinned.
  Relevant to our 24 GB/s link at low miss counts; not enabled.
- Pinned `load_experts_ranges` PadMap overload: upstream-internal (feeds the
  #1905 tiers); our stack never called the old form.
- Unsloth defaults: `STRATA_MMQ_KQ=1` (K-quant prompt kernels, x1.3-1.7 prompts
  on AMD with every expert in RAM; the kernels are `libstrata_kq.so`, opened
  only for q4_k/q5_k/q5_1/q6_k models - our IQ3_S pack never opens it; missing
  DSO degrades to the FP16 prompt path with one stderr line), `STRATA_HC_Q8=1`
  (HC projections read from the pack's own Q8_0 bytes: -36..-39% HC read per
  call, ~2 ms per window, answers change - only for packs that carry Q8_0 HC
  tensors; check before enabling on GSQ packs), `STRATA_ROUTE_TAIL_SKIP=0`
  where every expert is in RAM (setup writes it for Unsloth files; the engine's
  all-resident no-default rule is 43.1-era - no delta for us).
- `STRATA_COMMIT_BATCH` (on by default): the commit graph in one launch per
  layer kind; bitwise identical, engine-wide decode latency. Free.
- `STRATA_MTP_HIP_PRIO` (gfx12 draft-stream priority), `STRATA_VERIFY_ASYNC_
LAUNCH` (#2209), `STRATA_POOL_UMWAIT` (#2174), `--prefill-head-alias` (#2191,
8 GB cards), `STRATA_START_RETRIES` (engine start retries; 44.1.1 narrowed it to
no-signal exits and the message now names the exit status/AVX flags): opt-in or
diagnostics.
- #2228 picture-hash reuse fix: the server sends each picture's byte hash, the
  engine matches by hash + grid; a re-encoded picture no longer silently loses
  the cached state and the log says why. PLA sends pictures - this is exactly
  our class.
- Two-card split fixes: auto split takes the placement with the most spare
  VRAM on the fullest card among near-ties (#1440); the start-up VRAM check

**Regenerating the strata reference from the NEW strata - how:** the p9b window
computes the reference with `$B/app/kernel/strata` (the mounted kernel binary,
NOT the image's) and stamps each ref with sha256(kernel)[:16] beside
prompt/recipe (`ref-$i.stamp`, `REF=auto`). The reference regenerates by putting
the new kernel binary in place INSIDE the window:
```

KERNEL_VERSION=0144.1-fork KERNEL_SOURCE=stratasharp/0144-sexec \

```
The stamp changes, every `ref-$i` recomputes from the new engine, R1==R2 proves
its determinism, and the C# IDENTITY gate then compares the own path against the
NEW reference. (Never mix a stale ref with a new kernel - the stamp makes that
impossible.)
