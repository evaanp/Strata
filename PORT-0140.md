Branch `pla-0140` (worktree `~/strata-0140`), merging `v0.1.40` (1735d64, 307 commits after v0.1.39) into
our production line (`pla-0139-pipe`, the engine behind `strata:0.1.39-pipe1`). Merge commit `f0dcfc9`;
nothing was pushed, no other branch or worktree was touched.

Verdicts were decided by comparing behaviour against the released 0.1.40 code, not release notes.
Upstream's big changes this time: the verify window rewritten by the #783 series (6c37e47 batched K/V and
indexer append for the window, 57a2e08 final mixer read fused, f9b517b fused rope, 9dc3904 multi-token GR,
b968c27 shared-expert fork after the doorbell), `52c1fd6`/`a4d4c0f` pipelined verify windows, `db4d19f`
asynchronous adaptive expert tier (#876), `9ef43de` exchange rotation on top of it (#864), `321e3bb` MTP

## Conflicts and how they were resolved (f0dcfc9)

- `src/program/generate.cpp` (several hunks): upstream's `52c1fd6`/`a4d4c0f`/`9ef43de`/`db4d19f` replace our
  pipelined windows (17508ee), MTP chain (94882de) and async tier (e20a3da/e3f3716) - theirs is the same
  design on a wider base, and the auto-merge took upstream's versions of those regions. Re-applied only
  what production needs on top: the penalties-inside-the-pipelined-loop wiring (e455258). The RamFence
  remnant (our fence around the tier) was deleted: upstream fences the tier with `adapt_fence`.
  The merge also silently dropped three of our constructs - `park_view` rebuild, the disk-parking
  declarations/spill-tier rank on `park_current_body`, and a forgotten `--split-checkpoint` declaration.
  Commit `d3bb691` puts them back on upstream's `park_current_body` and extends the near-tail and
  message-boundary checkpoints to work under a layer split (stage parts at the same chunk boundary,
  incomplete set = no tail checkpoint). `docs/PROMPT_CACHE_TAIL.md` was amended by `b64a306`.
- `serve/server.py`, `serve/frontend.py`, `CMakeLists.txt`: both sides kept.
- Post-merge breakage found by the tests and fixed in `c412352`: `serve/test_server.py` lost the
  `MergingTokenizer`/`ContextCheckingEngine` helpers and the `SampledIds` class header (a stray ` @ours`
  marker sat where the class line was); and `pdl_parity.cpp` referenced `copy_rows_strided`, which upstream
  removed - the PDL drop is completed by deleting `src/kernels/pdl_parity.cpp`, `include/strata/kernels/pdl.hpp`
  and their CMake block (see the #904 verdict).

What our branch now carries over v0.1.40 (`git diff --stat v0.1.40 pla-0140`): 38 files, +3569/-271 -
`generate.cpp` (+1077 delta lines: parking, keyless hybrid, divergence logs, monitor fields, penalty

### #904 / PDL: why DROP, and what re-applying would mean

PIPE-0139 kept 18683c2 (PDL) because production ran it on the 5060 Ti (sm_120). That is no longer possible
on 0.1.40: upstream rewrote the verify window through #783 and 52c1fd6, and the merge adopted upstream's
path - no PDL hook survived anywhere (`grep STRATA_DF_PDL` after the merge matched only the dead files),
the launch sites are shaped differently (6c37e47 batching, 57a2e08 fused read, f9b517b fused rope, b968c27
fork), and `pdl_parity.cpp` even failed to compile against the new headers. Re-applying PDL is now a
port of #904 onto the #783 window - GPU-verified work (pdl_parity, verify_batch_parity, token identity),
which this CPU box cannot settle. PIPE-0139 never measured PDL's share; the box's spec-vs-nospec run with
and without PDL (impossible now) was the plan. Decision: drop for the image, list re-applying as an
optional box follow-up (box checklist).

## Decision 1: disk parking stays ours; upstream's session files sit beside it

`7733104` adds `conversation_file.cpp` (v1 format, POST /slots/0?action=save|restore, `SAVED|RESTORED
<tokens> <bytes> <ms>`). It is manual, per-slot, **single-GPU only - it refuses --layer-split** - and it
needs --prompt-cache > 0. PLA's flow (X-Strata-Conversation header, automatic delta parking, ~1-2 s
restore, every stage's live record under the split per 7cd0930, ~5 conversations cycling) cannot be built
on it without writing a dispatcher, a policy and a split path - strictly more own lines than the ~570 we
already have. So ours stays as is (`conversation_disk.cpp`, 100% coverage, split round-trip test green:
990/1668 checks). The two coexist without conflict: different files, different formats, no shared code.
`conversation_file_test` (upstream's, 185 checks) passes against our tree.

## Decision 2: near-tail and message-boundary checkpoints enabled

This is the fix for "a divergence deep in a 100K+ prompt falls back to the 16384 checkpoint". On our
branch it now works with the split and with both parkings:

- `--prompt-cache-tail` (flag; needs `--prompt-cache > 0` and `--prompt-cache-every > 0`, which the
  config already has at 16384): saves one extra checkpoint at the first chunk boundary within one chunk
  of the prompt's end. Under a layer split (our addition, d3bb691) it is saved from the stage parts at
  the same chunk boundary; if the parts are incomplete, no tail checkpoint. The tail is evicted first
  and the root is never dropped, so a full `--prompt-cache` never loses a periodic checkpoint to it.
- `STRATA_CACHE_MESSAGE_BOUNDARY=1` (env; needs --prompt-cache, --turn-token, --prompt-cache-root > 0):
  a checkpoint at the last real message boundary before the live turn (`message_checkpoint_boundary`,
  tail kind leaves first). Logs `message boundary checkpoint: <at> tokens, <tail> tail` when --trace.

Cost per checkpoint: identical to a parked conversation prefix at that length - the same stage images
plus the K/V up to the point. DETAILS.md measures ~118 MB for the turn-boundary checkpoints on the
production model at ordinary chat lengths; a near-tail checkpoint at 70-100K tokens is proportionally
larger (the periodic 16384-spaced ones are what the box already budgets), and the count is capped by
`--prompt-cache` (default 6) with the tail evicted first - so the extra ceiling is roughly one checkpoint
of tail size, not six.

## Decision 3: batch MTP and kv-grow stay off

`e5aed06` adds `--batch-mtp` and `2fbe321`/`10109e8` add `--kv-grow`; both default off, and our start
flags/config add neither. For us they would need: parallel requests (the batch-slot path, still mutually
exclusive with pipelined windows - the gate says so) and, for --kv-grow, a re-check of our disk-parking
K/V extent validation against an elastic pool. The box checklist includes one --kv-grow smoke so the
interaction is known before it is ever considered for production.

## What the orchestrator must run on the GPU box (hard gates)

1. Parity, all three scenarios, new image vs `strata:0.1.39-pipe1`, with the split the server's own args
   give (7d7e3de): `/root/apps/strata-disk/0139b/parity.sh` style - reuse / disk / mixed (A+B baseline
   sequential, candidate interleaved with C; disk for the id'd conversation, RAM for keyless). Token-for-
   token identity or the run fails.
2. Disk-parking under the split, production shape: five X-Strata-Conversation conversations cycling, a
   100K+ prompt, kill and restart the server, every conversation restores in ~1-2 s (`parking flags`
   lines green; the `does not continue its live end` logs on a deliberate divergence).
3. Spec vs nospec identity with `STRATA_DECODE_TIMING=1`, AND a second pair with a repetition penalty
   (>=0.05) to prove the pipelined penalty path (e455258) on upstream's window: penalty request must
   decode pipelined (STRATA_PIPELINE_DEBUG=1 banner) and stay token-identical to nospec+penalty.
4. Bench vs 0.1.39-pipe1 on split 17: prefill 73K and decode (target: no regression; upstream's #783
   window rewrite is expected to help - report the delta).
5. `--pipeline-windows 1` + `--adapt-async 1` now legal together (9ef43de integrates them): run the
   split-sweep PIPE-0139 planned, this time with both on. `conversation_snapshot_test` (skipped here) and
   `verify_batch_parity`, `kv_q4_parity` are part of the box test battery.
6. Decision-2 smoke: start with `--prompt-cache-tail` and `STRATA_CACHE_MESSAGE_BOUNDARY=1`; diverge
   deep in a long prompt and confirm the engine resumes from the near-tail / message-boundary checkpoint
   (trace lines) instead of 16384, under the split, with disk parking on.
7. `--kv-grow 1` smoke only (not production): serve, one long conversation, confirm the pool grows and
   our disk-park K/V extent validation still restores. Keep `--batch-mtp` off (batch slots, not ours yet).

Exact config diff for the new image vs 0.1.39-pipe1: add `--prompt-cache-tail` and the env
`STRATA_CACHE_MESSAGE_BOUNDARY=1`; everything else (splits, --conversation-disk-dir, --conversation-cache-mib,
--lock-experts-gib, STRATA_STAGE_CACHE_SLOTS) unchanged; `--batch-mtp` and `--kv-grow` absent (defaults off).
